# DevSetup

Десктопное приложение для Windows: сканирует окружение разработчика (приложения,
инструменты, пакеты, настройки), сохраняет его в файл `.setup` и после
переустановки системы восстанавливает одной кнопкой (через winget).

# Стек
- Python 3.13, PySide6 (Qt) для интерфейса
- Windows Package Manager (winget) для установки приложений
- Только Windows

# Текущее состояние (важно)
Desktop v0.2 реализован, облачный бэкенд Stage 3.1 реализован. Подключения desktop к облаку пока нет.



## Desktop (app/, test/)

- Сканеры в `app/scanner/`: Python, Git, VS Code, Docker, PostgreSQL, pip- и npm-пакеты, расширения VS Code, Git-конфиг (allowlist), переменные окружения (секреты отфильтровываются по имени), WSL, Windows Terminal (только чтение).
- Экспорт и импорт `.setup` (формат v2) в `app/backup/`.
- Сравнение с текущим ПК и восстановление через winget, `code`, pip, npm, wsl в `app/services/`.
- Интерфейс в `app/ui/`: главное окно, диалог восстановления, фоновые задачи.
- Тесты: `test/`, запуск проверен: 108 passed, 37 subtests passed.

## Cloud (cloud/)

- Django 5.2, Django REST Framework, SimpleJWT, PostgreSQL.
- `accounts`: пользователь с уникальным email, регистрация, вход, обновление токена.
- `setups`: CRUD для `.setup`, данные хранятся в JSONField, валидация формата v1/v2, проверка на секреты, изоляция данных по пользователю.
- Тесты: запуск проверен на PostgreSQL 18: 112 passed. Нужны запущенный PostgreSQL и `cloud/.env` (в git не попадает).

# Структура
- `main.py` - точка входа, создаёт QApplication и MainWindow
- `app/ui/` - окна и виджеты (только интерфейс, без логики сканирования)
- `app/scanner/` - сканеры: каждый находит один вид данных (приложения, VS Code
  расширения, pip/npm пакеты, git-конфиг, WSL и т.д.)
- `app/services/` - связывает сканеры и интерфейс
- `app/models/` - структуры данных
- `app/core/` - конфиг и общие утилиты
- `test/` - тесты

# Команды
- Окружение: `python -m venv .venv`, затем `.venv\Scripts\activate`
- Зависимости: `pip install -r requirements.txt`
- Запуск: `python main.py`
- Тесты: `pytest` (когда появятся)

# Правила кода
- Интерфейс отдельно от логики: в `app/ui` никаких вызовов winget и чтения системы.
- Долгие операции (сканирование, установка) выполнять не в главном потоке Qt,
  иначе окно зависает (QThread или QRunnable).
- Каждый сканер наследует базовый класс из `app/scanner/base.py` и возвращает
  список моделей из `app/models`.
- Установка должна быть идемпотентной: повторный запуск ничего не ломает.
- Ошибка установки одного приложения не останавливает остальные: логируем и
  показываем итоговый отчёт.
- Вызов winget через `subprocess.run([...], ...)` со списком аргументов,
  без `shell=True`. ID пакетов только из локально проверенного списка.
- Перед любой установкой показывать пользователю список и ждать подтверждения.
- Файлы `.setup` НЕ содержат пароли, ключи, токены и переменные окружения с секретами.
- Типизация (type hints) и короткие функции. Комментарии кратко, по делу.

# Нельзя
- Не читать и не править `.env`, `.venv`, `.git`.
- Не добавлять зависимости в `requirements.txt` без запроса.
- Не удалять и не менять ничего в системе пользователя без явного подтверждения.
- Не писать код, который скачивает и запускает файлы с неизвестных адресов.
- Не создавать новые файлы и папки в корне без необходимости.
